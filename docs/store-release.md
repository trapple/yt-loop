# Chrome ウェブストア公開の手引き

## 0. 審査の観点

yt-clip (録画する拡張) と違い、**yt-loop は動画を保存しない。** 再生位置を書き換えて
繰り返すだけで、YouTube 標準の「ループ再生」と同じ種類の操作に留まる。
ストリーミング動画のダウンロードを禁じる条項には当たらない。

気を付けるのは次の 2 点。

- **YouTube の意匠・名前を拡張の名前やアイコンに使わない。** 名前の `yt-` は略称として
  yt-clip で審査を通っている。アイコンは YouTube の赤と再生ボタンの形を避けてある
- 掲載画像に他人の動画を写さない (§4)

## 2. ダッシュボードに書く文面

そのまま貼れる形で持っておく。**実装と食い違うと審査で止まる**ので、
権限を足したらここも直すこと。

### 概要 (短い説明。manifest の description と同じ)

```
YouTube の指定した範囲を繰り返し再生する
```

### 説明 (詳細な説明)

```
YouTube の動画の「ここからここまで」を繰り返し再生します。
楽器・ダンス・語学の練習で、同じ箇所を何度も聴き直すときに使えます。

■ 使い方

プレイヤーを右クリックすると、YouTube 標準の「ループ再生」の下に項目が増えます。

1. ループしたい場面の頭で右クリックし「ここからループ」を押す
2. 終わりの場面で右クリックし「ここまでループ」を押す
3. 範囲がそろうと「ループ再生」が自動でオンになり、その範囲を繰り返します

・オン / オフは標準の「ループ再生」のチェックで切り替えます
・範囲を消すときは「ループ範囲を解除」を押します
・範囲はシークバーの上に帯で表示されます
・範囲の手前へシークすると、そこから再生して範囲に入ります (前奏から入りたいときに)

■ 動画ごとに覚えます

範囲とオン / オフは動画ごとに覚えます。同じ動画を開き直すと、前の範囲で続きを練習できます。

■ 画面を増やしません

新しいボタンやパネルは足しません。使うのは右クリックメニューだけです。

■ 集めている情報

ありません。開発者のサーバは存在せず、データを送る経路を持ちません。
範囲はお使いのブラウザの中 (この端末) にだけ保存されます。

ソースコード: https://github.com/trapple/yt-loop
```

### カテゴリ

仕事効率化 (どれにも合わなければ「娯楽」)

### 言語

日本語

### 単一用途 (Single purpose)

> YouTube の動画で利用者が指定した範囲 (開始〜終了) を繰り返し再生する。用途はこの 1 つに限られる。

### `storage`

> ループ範囲を設定した動画について、動画 ID・範囲 (開始と終了の秒数)・ループのオン / オフを端末内に保存する
> (`chrome.storage.local`)。同じ動画を開き直したときに範囲を戻すため。範囲を解除すると消す。

### ホスト権限 (content script `https://www.youtube.com/*`)

> YouTube のプレイヤーの右クリックメニューに「ここからループ」「ここまでループ」を足し、
> シークバーに範囲を表示し、再生位置が範囲の終わりを過ぎたら始まりへ戻すため。
> YouTube の中の移動 (ホームや検索結果から動画を開く) はページを読み込み直さないため、content script は
> YouTube のどのページでも読み込むが、動作するのは動画の再生画面だけで、ほかのページには何も差し込まない。

### リモートコードの使用

> 使用しない。すべてのコードはパッケージに含まれている。

### データの取り扱い (Privacy practices)

- 収集するもの: **なし** (どの項目にもチェックを入れない)
- 販売・移転: **しない**
- 用途外の使用: **しない**
- 範囲は端末の中 (`chrome.storage.local`) にだけ置き、同期もしない

## 3. プライバシーポリシーの公開

ダッシュボードは**ポリシーの URL** を求める。GitHub Pages で `docs/` を公開してある:

- URL: `https://trapple.github.io/yt-loop/privacy-policy`
- 設定: リポジトリの Settings → Pages → Source が `main` / `/docs`

## 4. スクリーンショット

```bash
npm run screenshots   # release/screenshots/ に 1280x800 を 1 枚
```

`1-menu.png` — 右クリックメニューに「ここからループ」「ここまでループ」が出て、記録済みの時刻が見え、
シークバーに範囲の帯が出ている状態。

**題材は Big Buck Bunny (Blender Foundation, Creative Commons)。** 掲載画像には
動画の中身がそのまま写るので、権利関係で問題にならないものを使う。
関連動画の欄は中身だけを隠す (他人の動画のサムネイルを写さないため)。

出力は 1280x800 / 24bit RGB / アルファ無しで、そのまま上げられる。
アップローダに形式を拒まれたら JPEG へ変換する:

```bash
sips -s format jpeg -s formatOptions 90 release/screenshots/1-menu.png --out release/screenshots/1-menu.jpg
```

## 5. 公開までの手順

```bash
npm run typecheck && npm test   # 通ることを確認
npm run package                 # dist を zip に固める
npm run screenshots
```

1. [Developer Dashboard](https://chrome.google.com/webstore/devconsole) で「新しいアイテム」
2. `release/yt-loop-<version>.zip` をアップロード
3. ストアの掲載情報 (説明・アイコン・スクリーンショット・カテゴリ) を埋める
4. プライバシーの項目に §2 の文面とポリシーの URL を入れる
5. 公開範囲を選ぶ (限定公開 = URL を知っている人だけ / 公開 = 誰でも検索できる)
6. 審査へ提出する (数日かかる)

**ダッシュボードの画面は自動操作もスクリーンショットも取れない** (Chrome の制約)。
文面は手で貼ることになるので、§2 をそのまま貼れる形に保っておく。

## 6. 版を上げるとき

**同じ版番号では再アップロードできない。** 公開のたびに上げること。

```bash
# 1. CHANGELOG.md の「未リリース」を版の見出しに書き換え、新しい「未リリース」を足す
# 2. 版を上げる (型チェックとテストが走り、通ればコミットとタグができる)
npm version patch    # または minor / major
# 3. zip を作る
npm run package
git push --follow-tags
```

版番号の出どころは `package.json` の 1 箇所だけで、`manifest.config.ts` は
それを読む。**manifest を手で直さないこと。**

更新公開では、ダッシュボードで新しい zip を上げ、変わったところ (説明文・スクリーンショット・
権限の説明) だけ差し替えて審査へ出す。「変更点」欄には `CHANGELOG.md` の該当する版を貼る。
